1 · IOS XE / Catalyst · Routing & Hardware

CEF Exception Adjacencies

CEF separates Layer-3 forwarding intent in the FIB from Layer-2 rewrite state in the adjacency table. A glean adjacency means a directly attached prefix exists but a host rewrite is not yet available; ARP resolves the host and builds that adjacency. Punt means special handling outside the normal CEF switching path, while null/discard/drop intentionally remove traffic. A healthy RIB/FIB therefore does not prove a usable rewrite.

Packet/state sequence: RIB → FIB longest-prefix result → adjacency pointer → cached rewrite or exception action → ARP/neighbor resolution where required → hardware realization. TAC workflow: prove the route, then adjacency, then neighbor state, then platform forwarding rather than resetting the routing protocol.

CLI
show ip cef <prefix> detail
show adjacency detail
show ip arp <ip>

2 · Catalyst 9000 · QoS/Hardware

Output Drops, Microbursts, and SoftMax

Output drops are egress congestion evidence and can occur during microbursts even when five-minute utilization is low. Cisco documents SoftMax as a queue threshold that allows additional consumption from shared buffer. In the cited Catalyst 9600 guidance the range is 100–4800 and default 100. This is finite shared memory, not new bandwidth.

Correlate interface output-drop deltas with FED queue statistics and determine whether the event is a transient burst or sustained oversubscription. Buffer tuning can absorb bursts; persistent offered load above line rate needs QoS, traffic engineering, or bandwidth. Recheck latency after tuning because deeper buffering can trade loss for delay.

CLI
show interfaces counters errors
show platform hardware fed active qos queue stats interface <interface>
qos queue-softmax-multiplier <100-4800>

Cisco source + figures: egress queue/buffer and microburst behavior

3 · Catalyst 9800 · Wireless

802.11r Fast Transition and PMK State

802.11r reduces authentication work during roaming through Fast Transition key hierarchy. Cisco's Flex local-authentication guidance supports over-the-air FT, not over-the-DS in that scenario, and supports FT+802.1X and FT+PSK. show wireless pmk-cache exposes DOT11R PMK state.

Troubleshoot WLAN FT policy → client capability/selected AKM → source client state → PMK cache → target AP/mobility → roam trace. Keep RF and authentication boundaries separate: healthy FT keys cannot fix a client that roams too late because of RF decisions.

CLI
show wireless pmk-cache
show wireless client summary
show wireless client mac-address <client-mac> detail

Cisco source + figures: FT flow and PMK cache

4 · Cisco ISE / Catalyst 9800 · Identity

dACL: Authorization Result to Packet Enforcement

A downloadable ACL is authorization content delivered through RADIUS and applied per client session. The chain is 802.1X/MAB → RADIUS → ISE authorization rule/profile → dACL → device download/install → packet enforcement. Access-Accept proves policy selection, not downstream enforcement.

Cisco documents no dACL support for FlexConnect local switching and IPv6 dACL with ISE 3.0+. Current 9800 guidance also records the IOS XE 17.8-and-earlier behavior where the ACL definition had to exist on each controller. Verify ISE Live Logs, returned authorization profile, device-installed client policy, then packets.

GUI
Policy > Policy Elements > Results > Authorization > Downloadable ACLs
Operations > RADIUS > Live Logs

Cisco source + figures: dACL workflow and scale table

5 · SD-Access · Campus Fabric

LISP Pub/Sub: EID-to-RLOC Control Plane

LISP tracks endpoint identity (EID) to fabric location (RLOC), while VXLAN carries the data plane. Cisco recommends LISP Pub/Sub for new SD-Access deployments with device image 17.6+, removing the normal internal-BGP dependency for fabric reachability distribution.

Healthy underlay IP reachability does not prove endpoint mapping. Verify the local LISP database, control-plane session, remote map-cache, then VXLAN forwarding. The cross-domain chain is endpoint authentication/authorization → VN/SGT → LISP publication → remote mapping → VXLAN → destination edge → TrustSec enforcement.

CLI
show lisp session
show lisp instance-id <id> ipv4 database
show lisp instance-id <id> ipv4 map-cache

Cisco source + figures: Pub/Sub architecture and fabric roles

6 · Catalyst SD-WAN · WAN

TLOC Extension: Borrowing the Peer's WAN Transport

TLOC extension lets one WAN edge use a transport physically attached to a neighboring edge. Cisco distinguishes L2 extension in a common subnet from L3 extension implemented with GRE. The cited feature history adds IPv6 TLOC extension at IOS XE Catalyst SD-WAN 17.11.1a.

Extension reachability is only transport plumbing. Prove extension forwarding → controller control connection → OMP TLOC advertisement → BFD/IPsec data-plane session → service route/policy. A reachable peer transport does not prove overlay forwarding.

CLI
show sdwan control connections
show sdwan bfd sessions
show sdwan omp tlocs
show sdwan interface

7 · Nexus 9000 / NX-OS · VXLAN EVPN

EVPN Route-Type Taxonomy

NX-OS documents Type-1 Ethernet Auto-Discovery, Type-2 MAC/IP Advertisement, Type-3 Inclusive Multicast, Type-4 Ethernet Segment, and Type-5 IP Prefix routes. Type-2 solves host reachability, Type-3 BUM/ingress-replication VTEP information, Type-5 routed prefixes, and Type-1/4 multihoming/ESI state.

An Established BGP session is not enough. Missing host: inspect Type-2. Broken BUM replication: Type-3 and NVE state. Missing routed prefix: Type-5 import into the L3VNI/VRF. Multihoming issue: ESI plus Type-1/4. Prove NLRI, route target, next-hop VTEP, import, and NVE forwarding.

CLI
show bgp l2vpn evpn
show bgp l2vpn evpn route-type 2
show bgp l2vpn evpn route-type 3
show bgp l2vpn evpn route-type 5
show nve peers

Cisco source + figures: EVPN multihoming, ESI, route types

8 · ACI / APIC · Troubleshooting

Atomic Counters and the APIC 6.1(2) Lifecycle Boundary

Historically Atomic Counters localized admits, drops, and excess packets between endpoints, EPGs, or TEPs and required fabric NTP. The critical current fact is lifecycle: Cisco's ACI Fundamentals 6.2 states that beginning with APIC 6.1(2), Atomic Counters are no longer supported.

Version-aware troubleshooting matters: an old runbook can point to a tool intentionally removed from a modern fabric. Establish APIC release first, then choose supported endpoint/COOP, zoning, interface/fabric counter, ELAM, fault, and current APIC workflows for the demonstrated boundary.

Operational caution
Verify APIC/fabric release before using historical Atomic Counter procedures.
Verify NTP for releases where Atomic Counters are supported.

9 · Secure Firewall / FTD · Packet Processing

Lina versus Snort Rule Ownership

Rules whose decisive criteria run in Snort—application, URL, geolocation—can appear on Lina as broad permit rules. Lina permits candidate traffic onward; Snort evaluates deep-inspection criteria and can deny/delete the session. A Lina ALLOW is therefore not an end-to-end allow.

Cisco notes packet-tracer may not show the actual Snort rule hit for the documented case and recommends live traffic with system support trace or system support firewall-engine-debug. The packet sequence is Lina preprocessing → candidate access handling → Snort classification → verdict → session continuation/deletion.

CLI
show cap <name> trace packet <n>
system support trace
system support firewall-engine-debug

Cisco source + figures: Lina/Snort representation and live verdict

10 · IOS XE · Programmability

Model-Driven Telemetry: Subscription Semantics

Telemetry subscriptions define YANG data, cadence/on-change behavior, encoding, and receiver. Dynamic subscriptions are dial-in; configured subscriptions are dial-out. Current Catalyst documentation shows yang-push with NETCONF dial-in, gRPC dial-out, and gNMI dial-in.

Restrictions matter: subtree filters are unsupported; when multiple receivers are defined only the first is attempted; data-access authorization checking is not supported in the described implementation. A working TCP session to a collector is not proof that the XPath/model path is valid or generating updates.

CLI
show telemetry ietf subscription all
show telemetry internal connection
show platform software yang-management process

11 · IOS XE / Catalyst · PKI

Certificate Revocation: CRL, OCSP, Ordered Fallback

revocation-check accepts ordered methods. If the first method returns an error, the next is tried. The keyword none means skip revocation checking if reached and accept the certificate; therefore revocation-check ocsp none favors availability during an OCSP failure. An explicit ocsp url overrides the AIA OCSP URL.

Troubleshoot chain trust, DNS/IP reachability, HTTP/LDAP transport, responder state, and configured fallback separately. Adding none can restore connectivity while weakening revocation assurance, so it is a security-policy decision, not a neutral fix.

CLI
crypto pki trustpoint <name>
 ocsp url <url>
 revocation-check ocsp crl
show crypto pki certificates
show crypto pki trustpoints

12 · Catalyst Center · Assurance

Path Trace: Calculated Path and Unsupported Boundaries

Path Trace computes a path from discovered topology and routing state; it is not a packet capture. Cisco lists unsupported cases including NAT/firewall, vPC/VSS/MLACP, ECMP over SVI, VACLs, overlapping IPs, and several fabric/wireless cases. LISP fabric Path Trace requires running traffic and cache on edge switches.

Validate discovery/topology freshness and whether the topology is inside the supported envelope. A Path Trace gap across an unsupported firewall or vPC boundary is not proof of forwarding failure. Move to device CLI, EPC/ELAM, or firewall tracing for the next real packet boundary.

GUI
Client 360 or Device 360 > Path Trace > Run New Path Trace
Use TCP/UDP flow details and ACL Trace where supported.
