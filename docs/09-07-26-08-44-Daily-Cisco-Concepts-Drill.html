Catalyst 9000 Embedded Packet Capture: observation point changes what a packet proves

Engineering deep dive

EPC is an observation point inside the forwarding pipeline, not automatically the final wire image. Cisco documents physical-interface attachment restrictions, a normal capture policer of 1000 pps, multicast replication visible only on ingress, CPU-injected packets absent from interface egress, and egress captures that may not reflect final hardware rewrites such as TTL, VLAN, CoS, checksum, or MAC changes. Security-feature visibility also depends on where the attachment point sits. Therefore choose the boundary deliberately, filter narrowly, reproduce briefly, inspect capture statistics for capture loss, and correlate EPC with FED or hardware counters. A missing packet may mean forwarding loss, feature-stage drop, or capture-policing loss; EPC alone does not distinguish them.

TAC-style evidence sequence

Define expected behavior → identify the last proven packet boundary → verify control-plane and forwarding state → inspect capture statistics and hardware counters → move the observation point only after the current boundary is proven.

monitor capture mycap match ipv4 any any
monitor capture mycap buffer circular size 1
monitor capture mycap start
show monitor capture mycap capture-statistics
monitor capture mycap stop
show monitor capture mycap buffer dump

Catalyst 9000 / IOS XE · Enterprise Routing · OSPF / BFD / Convergence · Expert

OSPF + BFD: faster liveness notification does not replace the OSPF neighbor state machine

Engineering deep dive

OSPF owns adjacency formation, LSDB synchronization, and SPF; BFD supplies a faster liveness signal after OSPF registers a Full neighbor. When BFD declares the peer down it notifies OSPF, which tears down the adjacency and reconverges. On broadcast networks Cisco notes OSPF BFD sessions are established with the DR and BDR rather than every visible router. Baseline BFD timers and OSPF registration are separate configuration layers. Hardware-offloaded sessions add a subtlety: non-50-ms-multiple Tx/Rx settings can be adjusted in hardware even though show bfd neighbors details displays configured values. Diagnose OSPF FSM → BFD registration/session → negotiated/detected liveness → physical loss/errors → OSPF teardown timestamp.

Cisco ISE / Catalyst Access · Identity / AAA · Authorization / dACL / RADIUS · Expert

ISE downloadable ACLs: Access-Accept is intent handoff; the NAD must download and enforce policy

Engineering deep dive

A dACL spans policy selection and network-device realization. ISE selects the authorization result, while the access device must obtain the referenced ACL and enforce it locally. Access-Accept therefore proves policy selection, not packet enforcement. ISE 3.5 includes built-in permit/deny IPv4/IPv6 dACLs and user-defined dACLs. Follow identity/EAP or MAB → matched authorization rule → authorization profile/dACL → RADIUS result → switch download → access-session state → real packet enforcement. If Live Logs are correct, move to the NAD boundary instead of repeatedly editing identity policy.

Catalyst 9800 · Wireless · 802.11r / Roaming / PMK · Expert

Catalyst 9800 802.11r: fast roaming is a key-hierarchy and client-capability problem

Engineering deep dive

802.11r changes key establishment; it does not force the client to roam. The client still chooses the target BSS. FT lets client and target AP derive and apply PTK material without repeating full authentication at every AP. Cisco supports Over-the-Air and Over-the-DS exchanges plus FT AKMs for 802.1X, PSK, and SAE. Current best-practice guidance recommends mixed FT and non-FT AKMs for heterogeneous fleets because FT-only excludes non-FT clients. Separate RF roam decision → client FT capability/WLAN AKM → FT exchange → PMK/key-cache state → reassociation → post-roam data path.

Cisco Secure Firewall / FTD · Security · High Availability / Stateful Failover · Expert

Secure Firewall stateful failover: role election, health monitoring, and connection replication are separate mechanisms

Engineering deep dive

FTD HA separates peer and role health, configuration synchronization, and connection-state replication. Stateful failover uses the state link to replicate supported NAT, TCP/UDP, Snort connection and inspection, ARP, bridge, IPsec, and selected application state; this does not mean every protocol is preserved identically. Interface-health policy is another independent failure input. Troubleshoot role/health → failover link → monitored-interface criteria → configuration sync → state-link statistics → connection replication → upstream/downstream convergence. A reset after failover can be unsupported state, missing replication, or return-path convergence; identify which boundary failed.
