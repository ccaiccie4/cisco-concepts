1. Catalyst 9000 QoS — proving microburst output drops in UADP hardware

Interface output drops are a symptom, not a root cause. On Catalyst 9000, the decisive boundary is the hardware egress queue. Cisco documents FED commands exposing queue configuration and per-queue enqueue/drop counters. HardMax is guaranteed buffer; SoftMax is dynamically shareable under DTS. A microburst can exhaust a queue while long-interval interface utilization still looks low.

Trace DSCP/CoS classification to the hardware queue, inspect HardMax/SoftMax and actual drop counters, then decide whether the correction is QoS remapping, buffer tuning, more egress bandwidth, EtherChannel, or removal of oversubscription. Priority queuing changes buffer behavior; it cannot manufacture bandwidth.

CLI: show platform hardware fed active qos queue config interface <interface>; show platform hardware fed active qos queue stats interface <interface>.

2. Catalyst 9800 Radioactive Trace — correlate one client across wireless processes

Always-on traces are the first evidence source, but conditional debugging/Radioactive Trace adds debug-level correlation for a selected client MAC when default trace depth is insufficient. Cisco documents clearing existing platform conditions, applying debug wireless mac <aaaa.bbbb.cccc> {monitor-time <seconds>}, reproducing the issue, and collecting correlated logs.

The engineering value is sequence: association, authentication, policy, mobility and forwarding events can be tied to one client instead of enabling broad debugs. Debug-level logging increases volume, so remove conditions and debugs after collection. Scope the MAC and time window before reproducing.

3. ISE Change of Authorization — policy change must reach the active NAD session

CoA changes authorization on an active RADIUS session or terminates it so a new session can be built. ISE exposes reauthentication and termination actions from live RADIUS sessions. Cisco warns that stale sessions can remain when a NAD does not send Accounting Stop/Off after reload, so the most recent session must be targeted.

Follow endpoint session → accounting/session identity → ISE CoA request → NAD lookup → ACK/NAK → reauthentication/termination → new authorization → enforcement. Saving a new ISE rule does not itself alter an already-established NAD session.

Cisco ISE CoA source

4. TrustSec SGACL matrix — source SGT × destination SGT selects policy

TrustSec SGACL enforcement is represented by a permissions matrix whose axes are source and destination security groups. Each matrix cell contains ordered SGACL policy for that pair. This is stateless security-group policy rather than a conventional address-centric ACL lookup.

Policy can be provisioned statically with cts role-based permission or dynamically from ISE depending on design. Prove source SGT, destination SGT, the exact permission cell, then hardware enforcement counters. If the SGT pair is wrong, editing SGACL lines treats the symptom instead of classification or propagation.

5. SD-Access policy extended nodes — enforcement moves closer to extended endpoints

A classic extended node is Layer 2 attached to a fabric edge; segmentation is enforced through VLAN-to-SGT mapping at the fabric edge. A policy extended node adds inline SGT tagging and SGACL enforcement on access ports and toward the fabric edge. It still uplinks via 802.1Q trunk/port-channel to one fabric edge, which supplies VXLAN encapsulation, LISP registration and anycast-gateway services.

Dynamic endpoint authorization can assign VLAN and SGT, enabling same-VLAN and inter-VLAN policy at the PEN. Troubleshooting therefore starts at endpoint authorization and PEN SGT/SGACL state before assuming the fabric edge is the first enforcement point.

6. Catalyst SD-WAN AAR — BFD measurement, SLA classification and fallback are separate

Application-Aware Routing measures tunnel loss, latency and jitter using BFD probes, calculates averages, classifies tunnels against SLA classes, then applies policy. BFD Up proves liveness, not that the path meets an application's SLA.

Preferred-color behavior is normally loose: other available paths can be used if preferred tunnels do not satisfy the SLA. Strict/Drop changes the outcome to drop; Fallback to best path is a distinct release-dependent option. Prove BFD, metrics, SLA thresholds, application classification, policy match, color constraints and selected TLOC in that order.

7. Nexus EVPN Type-5 — IP prefix reachability through the L3VNI

EVPN Type-5 advertises IPv4/IPv6 prefix reachability rather than endpoint MAC/IP reachability. NX-OS associates the route with the L3VNI RD and export route targets; the BGP EVPN next hop remains the VTEP, while gateway-IP can represent an overlay next hop in documented designs. Remote VRF import depends on route-target matching and policy.

Trace originating VRF route → EVPN export → Type-5 RD/RT/gateway/VTEP attributes → remote receipt → RT import → VRF RIB → recursive resolution → L3VNI forwarding. Type-2 is the neighboring mechanism for MAC/IP endpoint reachability.

Cisco Nexus Type-5 source and topology figures

8. ACI ELAM — prove the ASIC forwarding decision

ELAM is an ASIC-level diagnostic that triggers on the first packet/frame matching programmed conditions and exposes the forwarding decisions made by the ASIC. Cisco's ACI troubleshooting model asks which switch receives a flow, what decision it makes, and whether it drops it.

ELAM is not a continuous capture and does not require punting the target flow to CPU. Identify ingress leaf/ASIC and packet fields, reset/arm the trigger, reproduce once, confirm Triggered, dump the result, then interpret lookup, policy and egress decisions. This is the bridge from software intent to actual forwarding hardware.

Cisco ACI forwarding-tools source and ELAM figures

9. Secure Firewall Prefilter — Fastpath, Block and Analyze fork packet processing

Prefilter runs before normal access-control processing using limited outer-header criteria. Fastpath exempts matching traffic from further inspection/control including access control, identity, decryption and rate limiting; supported platforms can flow-offload eligible traffic. Block drops early. Analyze sends traffic onward to access control and deeper inspection using inner headers where applicable.

When expected IPS/ACP events are absent, first prove whether the flow matched Fastpath. Fastpathing a tunnel also fastpaths encapsulated connections, so tunnel scope matters. Prefilter is a packet-flow fork, not merely a performance hint.

Cisco Secure Firewall Prefilter source and policy figures

10. IOS XE Embedded Packet Capture — observe packets at the device

EPC captures packets flowing to, through or from IOS XE into DRAM and can export PCAP. Cisco documents monitor capture CAP match ..., monitor capture CAP start, monitor capture CAP stop, show monitor capture CAP buffer brief|detailed, export, and no monitor capture CAP.

Filters and rate limits matter because capture consumes CPU/memory. EPC proves arrival and packet headers at its capture point; it does not automatically prove every ASIC decision. Place ingress/egress captures around the suspected boundary, reproduce minimally, stop promptly, and correlate with forwarding state.

Cisco EPC configuration source

11. Catalyst Center Assurance — health depends on the telemetry collection pipeline

Assurance depends on telemetry collection. Cisco documents site-scoped settings for SNMP traps, syslog, NetFlow and wired-client data. The chain is site assignment → telemetry provisioning → device publication → transport → Catalyst Center ingestion/correlation → health/issues.

An empty or stale dashboard can therefore mean collection failure rather than a healthy network. Verify site assignment, manageability, configured destinations, device-side state, reachability, timestamps and ingestion before interpreting health scores.

Cisco Catalyst Assurance telemetry source and GUI figures

12. BGP RPKI Origin AS Validation — validation state is a policy input

RPKI origin validation compares a BGP prefix and origin AS with ROAs and assigns Valid, Invalid or Not Found. Invalid can mean an unauthorized origin AS or a prefix length beyond a matching ROA maxLength. Not Found means no ROA establishes validity or invalidity. RPKI validates origin authorization, not the entire AS_PATH.

IOS XE exposes match rpki {valid|invalid|not-found} in route-map configuration so local policy can act on state. Prove cache/ROA data and validation state before policy consequence. Validation and enforcement are separate boundaries, and platform/release defaults must be checked rather than assumed.
