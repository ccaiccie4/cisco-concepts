1. Catalyst 9000 UADP queue buffers and microbursts

UADP Packet Buffer Complex allocation is queue- and platform-dependent. Cisco documents 256-byte buffer units chained for larger frames. Short fan-in bursts can exhaust an egress queue while average utilization remains low. Prove class-to-queue mapping, output drops, platform queue counters and burst timing before changing buffer allocation. Platform, port speed, software and QoS queue count affect the baseline.

CLI
show interfaces <interface> counters errors
show policy-map interface <interface>
show platform hardware fed switch active qos queue stats interface <interface>

2. Catalyst 9800 Radioactive Trace for 802.1X

Radioactive Trace provides client-scoped chronology across association, EAP/RADIUS and policy state. Cisco's workflow is Troubleshooting > Radioactive Trace > Add > Start > reproduce > Stop > Generate. Correlate with ISE Operations > RADIUS > Live Logs. If needed, use controller packet capture; RADIUS AAA normally uses the Wireless Management interface.

3. ISE authentication versus authorization realization

802.1X has separate EAP identity, RADIUS authentication, authorization-result and device-enforcement stages. Access-Accept does not prove the intended VLAN, dACL or SGT was programmed. Use ISE Live Logs to identify Policy Set and authorization result, then verify the authenticator session and packet enforcement. The durable chain is identity proof → policy decision → returned attributes → device realization → packet.

Evidence
ISE: Operations > RADIUS > Live Logs

4. SD-Access Path Trace and LISP cache dependency

Cisco documents that Path Trace on a LISP fabric requires traffic to be running and cache to exist on edge switches. Path Trace is topology/routing-derived assurance, not an omniscient synthetic packet. Validate the support envelope first: NAT/firewall, vPC/VSS/M-LACP, VACL and several cross-fabric/wireless cases are unsupported. Then prove LISP map-cache and live traffic.

CLI
show lisp session
show lisp instance-id <id> ipv4 map-cache

5. SD-WAN AAR BFD buckets and multiplier

Application-Aware Routing measures loss, latency and jitter with BFD, aggregates samples into poll intervals and evaluates recent buckets with a multiplier. Cisco documents a 10-minute default poll interval and multiplier 6, so default classification can reflect roughly an hour. Reducing the multiplier speeds reclassification but increases sensitivity. Verify TLOC/BFD, measured metrics, SLA thresholds, policy match and fallback. Cisco also documents adjusted default SLA thresholds beginning with IOS XE Catalyst SD-WAN 17.15.1a.

CLI
show sdwan bfd sessions
show sdwan app-route stats
show sdwan policy from-vsmart

Cisco AAR source + SLA/BFD figures

6. Nexus VXLAN EVPN Multi-Site BGW boundary

Multi-Site preserves site-local EVPN domains and uses Border Gateways as the inter-site control, forwarding and failure-containment boundary. Internal VTEPs see external routes through BGWs; the DCI sees BGWs rather than every VTEP. Cisco documents a behavior change at NX-OS 9.3(5): reorigination is always enabled and prior next-hop rewrite behavior changed. Isolate local EVPN, BGW advertisement, DCI and remote import.

CLI
evpn multisite border-gateway <site-id>
show bgp l2vpn evpn summary
show nve peers

7. ACI endpoint classification to zoning realization

Troubleshoot contracts as endpoint classification/location, provider-consumer intent, compiled leaf zoning rule, then packet/ASIC behavior. APIC policy objects are intent; show zoning-rule is the leaf enforcement representation. If APIC shows a contract but the expected zoning rule is absent, the failure boundary is policy realization. Once present, ELAM can validate the packet's ASIC path.

8. Secure Firewall Lina-to-Snort verdict ownership

FTD processing crosses Lina and Snort. Deep-inspection criteria such as application, URL and geolocation can make Lina show a broad candidate allow before Snort makes the decisive verdict. Start with original tuple, NAT/xlate/connection and route, then inspect live Snort evidence. Cisco cautions that packet-tracer can miss the actual Snort rule hit in this scenario.

9. IOS XE Embedded Packet Capture boundaries

EPC uses a DRAM capture buffer plus capture point and can observe packets to, through or from the device. Associate point to buffer, start, reproduce, stop and export/analyze. Capture scope matters: Cisco documents restrictions such as ingress multicast capture without replicated egress copies in the cited implementation. Absence from EPC is not universal proof of absence from every ASIC replication path.

10. IOS XE Model-Driven Telemetry lifecycle and HA

Dynamic dial-in subscriptions are subscriber-created and tied to the session; configured dial-out subscriptions persist in running configuration and the device initiates to receivers. Cisco documents different HA behavior: dial-in sessions must be reinitiated after stateful switchover, while configured dial-out subscriptions automatically reconnect. Troubleshoot transport, subscription validity, YANG filter/model, encoding and source-data change.

CLI
show telemetry ietf subscription all
show telemetry ietf subscription <id> detail

Cisco MDT source + dial-in/dial-out figures

11. IOS XE PKI revocation as a runtime dependency

Successful enrollment does not guarantee later certificate authentication. Revocation checking through CRL/OCSP is a runtime dependency. Cisco notes CRLs over 5 MB can cause unexpected behavior and suggests OCSP, smaller CRLs or deliberately disabling revocation checks where the security design accepts it. Verify time, chain, SAN/identity, trustpoint, revocation method and CRL/OCSP reachability.

CLI
show crypto pki certificates
show crypto pki trustpoints
crypto pki trustpoint <name>
 revocation-check crl

Cisco PKI revocation source + CRL/OCSP figures

12. Catalyst Center Path Trace support envelope

Path Trace uses discovered topology/routing state and can show switched/routed/ECMP path, queue/drop information and ACL results. Cisco states ACL Trace is 100% accurate with a complete 5-tuple and best-effort with partial information. First classify a failed trace as unsupported scenario, stale/missing assurance state or genuine network failure; only the last category is direct forwarding evidence.

GUI
Client 360 / Device 360 > Path Trace > Run New Path Trace
