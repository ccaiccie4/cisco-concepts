Deep Dive 1

OSPF TI-LFA repair paths

TI-LFA uses Segment Routing to precompute OSPFv2 link, node, or SRLG repair paths where classic LFA/RLFA coverage is insufficient. Cisco targets sub-50-ms IP FRR. It requires SR and a prefix/node SID and is not supported on OSPF point-to-multipoint interfaces or MTR. Separate failure detection from repair programming: verify protected-prefix coverage and repair tunnels before failure.

CLI
router ospf <pid>
 fast-reroute per-prefix ti-lfa
show ip ospf fast-reroute ti-lfa tunnels

Deep Dive 2

BGP PIC Edge recursive convergence

PIC Edge preinstalls an alternate next hop so many prefixes sharing recursive forwarding state converge by changing a shared forwarding object rather than rewriting every prefix. Cisco requires a unique alternate next hop and recommends BFD for rapid detection. PIC solves data-plane convergence; a control-plane-only route reflector does not need it. Restrictions include BGP Best External incompatibility and single-failure protection.

CLI
show bgp ipv4 unicast <prefix>
show ip route <prefix>
show ip cef <prefix> detail

Cisco source + PIC forwarding figures

Deep Dive 3

Catalyst 9800 CAPWAP AP join

An AP needs IP before CAPWAP. Cisco documents Discovery Request/Response, DTLS, Join Request/Response, image check/download, Configuration Status, then RUN. Control/data use UDP 5246/5247. Discovery can use DHCP Option 43/52, DNS, L3 broadcast, static configuration, or remembered mobility peers. Localize failures to IP/discovery, DTLS, join, image, configuration, or keepalive.

CLI
debug capwap client events
debug capwap client error
debug dtls client error
debug dtls client event

Cisco source + CAPWAP session/discovery figures

Deep Dive 4

ISE EAP-TLS certificate chain

EAP-TLS validates certificate identity before authorization. ISE needs an EAP Authentication system certificate and the endpoint must chain to a trusted CA. EKU, SAN/name, validity, chain, and revocation can fail before authorization matters. Use ISE Live Logs to identify authentication versus authorization instead of treating every RADIUS failure as policy.

GUI
Administration > System > Certificates > Certificate Management > Certificate Signing Requests
Operations > RADIUS > Live Logs

Deep Dive 5

SD-Access VN/SGT segmentation

SD-Access separates a routed underlay from endpoint overlays. VNs are VRFs for macrosegmentation; SGT group policy supplies identity-centric microsegmentation. LISP supplies endpoint control services and VXLAN carries overlay data. Healthy underlay reachability does not prove overlay success. Verify VN/VRF, LISP database/map-cache, VXLAN, SGT and enforcement.

CLI
show lisp session
show lisp instance-id <id> ipv4 database
show lisp instance-id <id> ipv4 map-cache
show cts role-based sgt-map all

Deep Dive 6

SD-WAN OMP route-to-TLOC dependency

OMP is the overlay control protocol. Destination routes and TLOC transport attachments are different objects. An OMP route can exist while its selected TLOC is unavailable or BFD data-plane session is down. Trace OMP route → TLOC → control connections → BFD → service-VPN RIB/FIB → packet. Route visibility alone is not forwarding proof.

CLI
show sdwan omp routes
show sdwan omp tlocs
show sdwan control connections
show sdwan bfd sessions

Deep Dive 7

VXLAN EVPN Type-2 to NVE forwarding

NX-OS uses BGP EVPN to advertise MAC/IP bindings and VXLAN for data. The chain is local endpoint learning → L2RIB/EVPN Type-2 → remote import → NVE/VTEP forwarding. RD provides uniqueness and RT controls import/export. A Type-2 route does not prove NVE peer/VNI health; an NVE peer cannot compensate for a missing endpoint route.

CLI
show bgp l2vpn evpn
show l2route evpn mac all
show nve peers
show nve vni

Cisco NX-OS guide + EVPN/NVE figures

Deep Dive 8

ACI endpoint-to-contract evidence

Cisco's endpoint workflow inspects endpoint status, tunnel status, traceroute, atomic counters, then contracts. Endpoint learning establishes location; tunnels provide reachability; contracts define permission; atomic counters localize packet loss. Correlate APIC intent with leaf zoning realization and packet evidence rather than making policy the default explanation.

CLI
show endpoint ip <ip> detail
show zoning-rule
show zoning-rule scope <vrf-scope>

Cisco APIC guide + endpoint/atomic-counter figures

Deep Dive 9

Catalyst 9800 HA SSO synchronization

HA SSO mirrors AP/client state from Active to Hot Standby so RUN-state APs and clients can survive controller failure without AP rediscovery. RP synchronizes redundancy state; RMI+RP supports gateway-reachability decisions. Client SSO does not preserve clients that have not reached RUN. Verify peer state and configuration/AP/client synchronization before planned switchover.

CLI
show redundancy
show wireless stats redundancy config database
show wireless stats redundancy client sso
show wireless stats redundancy ap sso

Cisco HA guide + RP/RMI/state-sync figures

Deep Dive 10

StackWise Virtual dual-active protection

StackWise Virtual creates one logical system from two supported switches. SVL carries the virtual-system relationship; dual-active detection protects against split brain if that relationship is lost. Cisco enables StackWise Virtual globally and applies DAD under an interface. Verify role, SVL, DAD and forwarding independently; DAD does not replace SVL design.

CLI
stackwise-virtual
 domain <id>
interface <interface>
 stackwise-virtual dual-active-detection

Cisco command reference + SVL/DAD material

Deep Dive 11

Secure Access Resource Connector path

Resource Connectors are lightweight VMs that provide Secure Access a path to private resources; connector groups form the private-access operational boundary. Correct user authorization does not prove connector health or resource reachability. Cisco guidance covers connector monitoring, diagnostics, and connector-group upgrade windows. Trace policy → connector group → cloud reachability → DNS/resource route/firewall → application.

GUI
Secure Access: Resource Connectors and Connector Groups > Monitor / Diagnostics

Cisco Secure Access Help + connector architecture/status figures

Deep Dive 12

YANG management named AAA method lists

IOS XE can bind named AAA authentication and authorization lists to YANG management interfaces. Cisco documents gNMI, NETCONF and RESTCONF support and serial processing until success or exhaustion. TCP/SSH/HTTPS can therefore work while API AAA fails. Introduced in 17.9.1. Verify listener, method-list binding, backend, authentication, authorization, then RPC/YANG operation.

CLI
netconf-yang
yang-interfaces aaa authentication method-list <name>
yang-interfaces aaa authorization method-list <name>
show platform software yang-management process
