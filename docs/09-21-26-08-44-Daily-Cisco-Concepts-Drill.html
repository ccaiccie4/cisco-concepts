Lesson 1 · Routing

BGP Optimal Route Reflection

A conventional RR chooses its best path from its own topological position. If earlier BGP attributes tie, its IGP distance to the next hop can make it advertise an exit that is poor from a client's location. ORR performs reverse-SPF from a configured client/root viewpoint so the reflected best path can follow the client's IGP perspective. IOS XR applies ORR per address family and requires link-state topology. Co-located clients can share a root calculation. Troubleshoot candidate paths → link-state database → ORR root/group → rSPF cost → advertised path → client FIB. ORR cannot select a route the RR never learned.

Lesson 2 · Wireless

Catalyst 9800 Radioactive Trace

Radioactive Trace correlates a single client's events across controller processes. Follow association → security/key establishment → AAA → policy resolution → mobility → IP learning → RUN/data forwarding. The first incomplete transition is the useful failure boundary. Collect a bounded MAC-scoped trace, reproduce once, stop it, and align timestamps with OTA/wired packet captures. Global counters provide context but do not replace client-state evidence.

Lesson 3 · Identity

ISE downloadable ACL delivery

Authentication success is only the first boundary. ISE returns an authorization result naming a dACL; the NAD then sends a RADIUS request containing aaa:event=acl-download, receives ACEs, creates the local ACL, binds it to the authenticated session and programs enforcement resources such as TCAM. A RADIUS Access-Accept can therefore coexist with missing enforcement. Prove authentication → authorization profile → ACL reference → download exchange → local ACL → session binding → hardware counters.

Lesson 4 · Identity

TrustSec SGACL matrix and hardware enforcement

TrustSec policy is a source-SGT × destination-SGT permissions matrix. Correct source classification alone does not prove policy: destination mapping must be right, the intended matrix cell must resolve to the expected ordered SGACL, and the switch must program it. Cisco exposes role-based counters for runtime evidence and documents hardware caveats for punt/CPU-bound traffic. Trace source SGT → destination SGT → matrix → downloaded SGACL → ASIC state → counters → packet result.

Lesson 5 · Campus

SD-Access LISP map-cache

Fabric edges register endpoint-to-RLOC location with the control plane; ingress edges resolve destinations and cache mappings before VXLAN can forward toward the remote RLOC. Healthy underlay reachability does not compensate for stale or absent endpoint mapping, and correct mapping cannot compensate for an unreachable RLOC. Trace endpoint registration → control-plane database → ingress map-cache → RLOC underlay reachability → VXLAN encapsulation → egress endpoint state.

Lesson 6 · WAN

Catalyst SD-WAN restricted colors

Colors describe WAN transports and influence tunnel formation. The restrict behavior can intentionally prevent BFD sessions between unlike colors, commonly keeping private MPLS TLOCs from pairing with public transports. OMP may advertise a TLOC even when color/restrict semantics prevent a usable BFD tunnel. Troubleshoot selected OMP route/TLOC → local/remote colors → restrict → NAT/reachability → BFD → FIB rather than changing route preference to fix a transport-pairing rule.

Lesson 7 · Data Center

VXLAN EVPN symmetric versus asymmetric IRB

Asymmetric IRB routes at ingress and carries the packet in the destination L2 VNI; egress primarily bridges, so relevant L2 VNIs must exist more broadly. Symmetric IRB uses an L3 VNI/IP-VRF transit between VTEPs, with each VTEP handling its local bridge/routing boundary. Troubleshoot source MAC-VRF → ingress route lookup → chosen L2/L3 VNI → remote NVE → destination VRF/MAC-VRF → host. Route tables alone do not prove the expected VNI transition.

Lesson 8 · Data Center

ACI contracts become leaf zoning rules

APIC objects express intent, but leaf hardware enforces packets. Endpoint/COOP state supplies location, classification supplies source/destination class, and contracts/filters compile into zoning rules. A contract can exist in APIC while a packet fails because class, scope, direction or runtime programming differs. Work source endpoint/class → destination endpoint/class → contract → leaf zoning rule → hit/action → ELAM or capture. The leaf rule is executable evidence.

Lesson 9 · Security

Secure Firewall TLS decryption boundary

TLS inspection must match decryption policy and complete the relevant handshake before later application inspection can behave as expected. Cisco Connection Events can identify the matched decryption rule and TLS errors when logging is enabled; TLS counters provide the next evidence tier, while verbose SSL debug is TAC-oriented. Trace tuple → decryption rule → handshake/certificate → TLS counters → ACP/Snort → egress. Missing encryption details first calls for logging verification, not an assumption that decryption was bypassed.

Lesson 10 · Campus

StackWise Virtual Dual-Active Detection

If all SVLs fail, the standby promotes because it cannot distinguish active failure from isolation; if the former active remains alive, both can claim the same logical identity. DAD resolves that ambiguity. Fast Hello uses dedicated links; enhanced PAgP propagates active-switch identity through a neighboring Cisco switch. The DAD port must not be the SVL port. Trace SVL members → SSO roles → independent DAD path → active-ID/recovery → MEC state → disabled/recovery interfaces.

Lesson 11 · Automation

Catalyst Center Path Trace is computed assurance

Path Trace correlates discovered topology and routing state; supported workflows can add ACL trace, statistics and live capture. It has explicit limitations including NAT/firewall and several vPC/VSS/fabric cases. LISP fabrics require traffic and edge map-cache state. A complete 5-tuple gives the strongest ACL-trace accuracy. Use Path Trace to localize a suspected hop, then prove that hop with native counters/capture; a visualization gap can be a tool limitation rather than a forwarding failure.

Lesson 12 · Automation

IOS XE on-change telemetry dampening

On-change YANG telemetry can overload publisher and collector when leaves change rapidly. For supported native TDL telemetry, a dampening period coalesces changes and sends the latest changed records at interval end; zero means no dampening. Support depends on model/filter/platform, and show telemetry ietf subscription <id> detail exposes unsupported combinations. Trace subscription validity → stream/filter → on-change support → dampening → receiver → update cadence/resource pressure. Dampening trades some immediacy for bounded update rate.

Concept connections / diagnostic reference

802.1X → RADIUS → ISE → dACL/SGT: identity decision precedes NAD download/programming. SDA → LISP → VXLAN → TrustSec: LISP answers where, VXLAN transports, SGT says who, SGACL says whether. ACI endpoint → COOP → zoning → ASIC: location/class precede enforcement. EVPN → MP-BGP → NVE: IRB model determines VNI transition. Intent → hardware: controller state is not packet proof.

show cts role-based counters verifies TrustSec policy hits. dACL evidence includes aaa:event=acl-download. MDT detail exposes unsupported dampening. For DAD, verify independent Fast-Hello/ePAgP evidence rather than only SVL/MEC health.
